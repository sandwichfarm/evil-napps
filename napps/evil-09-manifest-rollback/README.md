# evil-09 — manifest rollback

**Tier 3 — what even a perfect launcher can't stop.** The fetch-side half of
the unverified-bytes gap evil-08 opened in-frame: NAPP.md's entire
publication story is "a napp is an app published as kind `35130`" + "the
launcher serves published files through a service worker backed by local
storage" — no selection rule, no verification, no pinning. The reference's
practice (validated from source, `src/nsite/fetch.ts`) is an author-bound
REQ to untrusted relays, newest `created_at` wins, files fetched by sha256
from the manifest's path tags. **A relay withholding the newest manifest
serves an older, valid, signed one — and the launcher installs it.** Rollback
needs no forgery: the older manifest is as legitimate as the newest.

Demonstrated end-to-end, not from source: this rung ships two mock relays
(`tests/_mockrelay.mjs`) serving **real BIP340-signed kind 35130 manifests**
(`fixtures/`, generated from this rung's own built bytes by
`tools/make-evil09-fixtures.mjs`, re-verified in every spec run), and the
harness gained a faithful `fetchManifest` miniature behind a **manifest
source** knob.

This folder is the NAPP artifact: `index.html` + `metadata.json`, built from
`src/napps/evil-09-manifest-rollback/` via `node build.mjs`; `fixtures/` is
regenerated by the same build and committed alongside.

## Rows

| id | attack | target | severity |
|----|--------|--------|----------|
| `rollback-bytes` | manifest rollback — which manifest's bytes am I running? | kind 35130 selection is newest-created_at-wins from untrusted relays; a withholding relay chooses the bytes | critical — **arms under the relay-withhold knob** |
| `no-pin` | no content addressing anywhere | the install record (d tag + instance id) pins no manifest hash; the user approved a NAME | critical — honest `na` in-frame (nothing to detect) |

## Arming (harness knobs)

- **manifest source = local** (default): the rung is quiet — `rollback-bytes`
  held (it *is* the newest bytes; nothing verified that, but nothing withheld
  it either), `no-pin` an honest `na`.
- **manifest source = relay** (run `node tests/_mockrelay.mjs 9101` first):
  the harness asks two relays for the kind 35130 manifest, exactly like the
  reference's `fetchManifest`. relay-a (the author's write relay) is hostile —
  it ignores the REQ filter and serves everything it has; the launcher's
  client-side author binding drops the foreign clone (**the honest
  counterpoint: id takeover is held, because the reference binds manifests
  by author pubkey**). Newest `created_at` wins among the author's answers →
  v2 → held.
- **+ relay-a withholds the newest** (the `withhold` knob): relay-a serves
  only v1. The launcher still does everything right — author-bound,
  newest-wins over what it was shown, sha-verified files — and installs the
  older signed manifest anyway. The relaunched frame detects it **only because
  this rung embeds its own version marker**; nothing in the protocol would.
  `rollback-bytes` arms: **ROLLBACK PROVEN**.

## VERY EVIL

Sends the rollback evidence (running version, instance, origin, the
withheld-newest note) to the collector. No destructive payloads — the harm
here is done by the launcher's own fetch, exactly as specified.

## Validate

```bash
node build.mjs                        # regenerates the signed fixtures from the built bytes
node tests/_mockrelay.mjs 9101 &      # the two virtual relays (or let the spec spawn it)

```

The fixtures are real: every spec run re-verifies each manifest's id (sha256
of the serialized event) and BIP340 signature — "a valid, signed, older one"
is machine-checked, never asserted. Validated findings:
[ROADMAP.md](../../ROADMAP.md); the protocol-level claim lives in
